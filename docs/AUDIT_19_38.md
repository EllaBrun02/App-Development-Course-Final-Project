# Audit Findings 19–38 — Fix Summary

Branch: `fix/audit-19-38` (from `main`). Companion to the 1–18 fixes on `fix/audit-01-18`.

| # | Finding | Fix |
|---|---------|-----|
| 19 | Comment limit bypass via `_did` cookie | Cookie is now HMAC-signed + httpOnly (forged/edited cookies rejected), plus a per-IP backstop limit (10/min). `middleware/rateLimit.js`. A cookie can never identify a device with certainty — this narrows the bypass as far as cookies allow. |
| 20 | Deleting an article leaves orphaned comments/view stats | `deleteArticle` now also deletes the article's comments and view-stat records and logs the counts. `controllers/editorController.js`. |
| 21 | Publish markers on the graph stick to the previous time range | The marker plugin is created per chart instance (no global `Chart.register`) and reads its points from the current chart's own options, so range switches always redraw correctly. `public/js/analytics.js`. |
| 22 | Chart distances don't represent real time | The client builds a continuous hourly series (missing hours = 0 views), so equal spacing = equal time. Multiple update events in one hour are shown with a `×N` marker and each event time is listed in the tooltip. |
| 23 | Direct editor edits not recorded in statistics | `editArticle` records a publish event whenever it changes a published article's live content. |
| 24 | No demo articles with multiple approved updates | The seed gives ~10 published articles 2–3 additional update events spread between publication and now, with surrounding view data. |
| 25 | Seed generates views in the future | Stat buckets are only generated for hours that already passed (`hour <= now`), and comment timestamps are clamped to the present. |
| 26 | Weather can silently be older than 15 minutes | Data older than the TTL after a failed refresh is flagged `stale` and the widget shows a "may be out of date" warning; with no cache at all it shows "Currently unavailable". Open pages refresh the widget every 5 minutes via the new `/api/weather` endpoint (`public/js/weather.js`). |
| 27 | Thundering herd of weather requests on cold cache | Concurrent callers share a single in-flight refresh promise; only one external request goes out. `utils/weather.js`. |
| 28 | Performance at scale unproven | Editor dashboard is paginated on the server (50/page with page controls); the analytics API filters the requested time range server-side (`?hours=`); added indexes matching real queries (`status+views`, `author+updatedAt`). |
| 29 | Related writes can partially succeed | View recording is ordered and compensated: the hourly bucket is incremented first, and if the total-counter update fails the bucket increment is rolled back, keeping the two counts consistent. `controllers/publicController.js`. |
| 30 | Editor comparison screen incomplete | Both versions now show their image (with an explicit "Image changed" badge and "No image"/load-failure placeholders) and the full content, safely escaped with real line breaks (`white-space: pre-line`) — no more literal `<br>` text. No external diff library is used. |
| 31 | System messages not accessible | Save/error/action messages have `role="status"`/`role="alert"` + `aria-live`; errors receive keyboard focus so screen readers announce them; all programmatic smooth scrolling (and CSS `scroll-behavior`) respects `prefers-reduced-motion`. |
| 32 | Feed state lost; sidebar unreachable on mobile | Search/category/viewed/sort are reflected in the URL (`history.replaceState`) and restored on load, so refresh/back/share keep the state. On mobile the home sidebar (weather + categories) is placed before the feed. |
| 33 | Broken image URLs not handled | Feed cards fall back to the 📰 placeholder when an image URL fails to load; the article hero hides itself on load failure; space is reserved (min-heights) so late loads don't shift content. |
| 34 | Login/session hardening | No known default session secret (env var, else a random secret persisted to a gitignored file — sessions still survive restarts); login attempts limited to 10 failures / 15 min per IP; session ID regenerated on login (anti-fixation); session cookie httpOnly + SameSite=Lax; state-changing requests with a mismatched `Origin`/`Referer` are rejected (CSRF mitigation). |
| 35 | Tests could mislead | Added `tests/audit-19-38.test.js` (run with `npm run test:audit` against a running, seeded server, `BASE_URL` configurable): the spam test keeps its cookies like a real browser, verifies the 4th comment is blocked and that forged cookies are rejected; also checks the weather API, cross-origin rejection, session regeneration, and the analytics range filter (incl. no future buckets). |
| 36 | Run instructions didn't match reality | `HOW_TO_RUN.md`/`SETUP.md` rewritten: cross-platform, no personal paths, explicit `PORT`/`MONGO_URI` overrides, and a prominent warning that seeding wipes the database. The seed script itself now warns and requires confirmation (`--yes` to skip). |
| 37 | Git history couldn't be verified from the ZIP | Not a code bug. The project's Git repository lives at github.com/EllaBrun02/App-Development-Course-Final-Project — submit the repository link with the ZIP (as the course requires) so branches, commits and pull requests are verifiable. Each member should contribute from their own account. |
| 38 | Is a Diff library allowed? | On `main` no external diff library is used: the editor comparison is a side-by-side view built with our own code (kept that way in fix #30). If a diff-highlighting library is ever added, clear it with the lecturer first. |
