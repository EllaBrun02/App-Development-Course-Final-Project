# Audit Findings 19–38 — Fix Summary

Originally implemented on `fix/audit-19-38`; reconciled with the merged `dev` code and the submission-readiness fixes. See `SUBMISSION_FIXES.md` for current verification and limitations.

| # | Finding | Fix |
|---|---------|-----|
| 19 | Comment limit bypass via `_did` cookie | HMAC-signed cookie plus a three-attempt rolling limit for both device and IP. Atomic MongoDB reservations survive restarts and multiple processes. People sharing an IP share its allowance; this is a conservative fallback, not proof of physical-device identity. `middleware/rateLimit.js`. |
| 20 | Deleting an article leaves orphaned comments/view stats | `deleteArticle` now also deletes the article's comments and view-stat records and logs the counts. `controllers/editorController.js`. |
| 21 | Publish markers on the graph stick to the previous time range | The marker plugin is created per chart instance (no global `Chart.register`) and reads its points from the current chart's own options, so range switches always redraw correctly. `public/js/analytics.js`. |
| 22 | Chart distances don't represent real time | The client builds a continuous hourly series (missing hours = 0 views), so equal spacing = equal time. Multiple update events in one hour are shown with a `×N` marker and each event time is listed in the tooltip. |
| 23 | Direct editor edits not recorded in statistics | Merged `dev` blocks direct edits to live published content. Corrections go through the pending version and approval records the update event. |
| 24 | No demo articles with multiple approved updates | Full seed includes multi-update histories. `npm run demo:updates` also adds three fictional examples to an existing database without deleting work; each has three publication events and before/after hourly views. |
| 25 | Seed generates views in the future | Stat buckets are only generated for hours that already passed (`hour <= now`), and comment timestamps are clamped to the present. |
| 26 | Weather can be older than 15 minutes | Freshness is measured from the provider observation time. Expired or invalid observations return unavailable values. The browser clears numbers at their expiry deadline and checks again after visibility/history restoration; it also polls periodically. |
| 27 | Duplicate weather requests on cold cache | Concurrent callers share one refresh promise. An upstream failure triggers a one-minute retry backoff, while visitors receive an unavailable state. |
| 28 | Performance at scale unproven | Editor dashboard is paginated on the server (50/page with page controls); the analytics API filters the requested time range server-side (`?hours=`); added indexes matching real queries (`status+views`, `author+updatedAt`). |
| 29 | Related writes can partially succeed | View recording compensates if the article counter update fails after the hourly increment. This reduces inconsistency but does not make the writes transactional; rollback failure and process interruption remain limitations. |
| 30 | Editor comparison screen incomplete | Both versions include escaped full text, line breaks and image choices before JavaScript enhancement. The optional Diff library remains in `dev`; it was deliberately left unchanged in the submission fixes. |
| 31 | System messages not accessible | Save/error/action messages have `role="status"`/`role="alert"` + `aria-live`; errors receive keyboard focus so screen readers announce them; all programmatic smooth scrolling (and CSS `scroll-behavior`) respects `prefers-reduced-motion`. |
| 32 | Feed state lost; sidebar unreachable on mobile | Search/category/viewed/sort are reflected in the URL (`history.replaceState`) and restored on load, so refresh/back/share keep the state. On mobile the home sidebar (weather + categories) is placed before the feed. |
| 33 | Broken image URLs not handled | Feed cards fall back to the 📰 placeholder when an image URL fails to load; the article hero hides itself on load failure; space is reserved (min-heights) so late loads don't shift content. |
| 34 | Login/session hardening | No known default session secret (env var, else a random secret persisted to a gitignored file — sessions still survive restarts); login attempts limited to 10 failures / 15 min per IP; session ID regenerated on login (anti-fixation); session cookie httpOnly + SameSite=Lax; state-changing requests with a mismatched `Origin`/`Referer` are rejected (CSRF mitigation). |
| 35 | Tests could mislead | Verification scripts and their ZIP were removed from the submitted branch at the team’s request and kept separately. Private checks cover behavior: cookie resets, persistence, concurrency, weather expiry and non-destructive demo preparation. Passing payload-shape checks alone does not prove compliance. |
| 36 | Run instructions did not match reality | Guides now use the lockfile install, document environment settings, distinguish destructive seed from additive demo preparation, describe current files/features, and explain packaging without dependencies/logs/secrets/tests. |
| 37 | Git history couldn't be verified from the ZIP | Not a code bug. The project's Git repository lives at github.com/EllaBrun02/App-Development-Course-Final-Project — submit the repository link with the ZIP (as the course requires) so branches, commits and pull requests are verifiable. Each member should contribute from their own account. |
| 38 | Is a Diff library allowed? | The optional Diff CDN dependency is still present on `dev`. Course approval/removal is intentionally outside the requested submission-fix scope; no approval is claimed. |
